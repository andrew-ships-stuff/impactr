# Performance

Impactr bounds analyzer concurrency, sorts canonical output, caches graphs by source/config/analyzer hashes, and runs before/after analyzers concurrently. Embedded inference has a separate thread budget to avoid CPU oversubscription.

## Reproduce deterministic benchmarks

```bash
go test -run '^$' -bench . -benchmem ./internal/analysis ./internal/graph ./internal/render
```

The source benchmark parses 100 Go files, the graph benchmark traverses a 5,000-node chain with depth and budget bounds, and the render benchmark produces a 250-node SVG.

## Recorded deterministic baseline

Measured 2026-11-15 on Apple M5, macOS arm64, Go 1.26.2 with `-benchmem`:

| Benchmark | Time/op | Bytes/op | Allocs/op |
| --- | ---: | ---: | ---: |
| Go analysis, 100 files | 3.057 ms | 900,278 | 10,920 |
| Blast radius, 5,000 nodes | 0.380 ms | 1,424,204 | 5,077 |
| SVG render, 250 nodes | 0.268 ms | 164,967 | 4,408 |

These are one-machine baselines, not cross-platform claims. Go's benchmark harness does not report peak RSS or whole-process CPU utilization.

## Embedded sample

On the same machine, one complete model/context initialization plus constrained 64-token structured generation with the checksum-pinned Qwen2.5-0.5B Q4_0 took **4.927 s/op**. Native GGUF allocations are not fully represented by `-benchmem`; this single sample is a functional baseline, not a latency distribution or GPU comparison.

For a publishable inference study, record model hash, quantization, OS, CPU, threads, context, time to first token, tokens per second, and peak RSS.
