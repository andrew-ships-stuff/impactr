# GitLab CI

The checked-in `.gitlab/impactr.gitlab-ci.yml` uses exact merge-request endpoints and the same engine as local and GitHub workflows.

## Current job

```yaml
impactr:
  stage: test
  image: golang:1.26-bookworm
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  variables:
    IMPACTR_PROVIDER: "none"
  before_script:
    - go install github.com/andrew-ships-stuff/impactr/cmd/impactr@${IMPACTR_VERSION:-latest}
  script:
    - impactr analyze --base "$CI_MERGE_REQUEST_DIFF_BASE_SHA" --head "$CI_COMMIT_SHA" --output .impactr
  artifacts:
    when: always
    paths: [.impactr/]
    expire_in: 14 days
```

## Authentication and updates

The artifact-only job above preserves the exact merge-request comparison. A native `impactr gitlab comment` command exists and can upload PNGs and update the marked note, but it currently performs its own analysis using configured refs instead of publishing the already generated bundle. Until an `--existing` mode is implemented, do not append it to this exact-endpoint job unless the configured comparison is intentionally equivalent.

When using native note publishing, set a masked, protected `GITLAB_TOKEN` with the minimum API access needed for project uploads and merge-request notes. Without it, artifact analysis still succeeds.

## Fork trust boundary

Do not expose protected variables to untrusted fork pipelines. Use artifact-only analysis and a separately trusted publisher that validates the bundle and pipeline identity.

Project-upload media visibility depends on GitLab instance settings.
